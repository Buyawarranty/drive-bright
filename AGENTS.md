# Project architecture rules
- Customer/lead pop-ups and notification bells share a fail-closed current-assignee check for sales and sales leads, including WhatsApp replies and policy-linked authorisation results; unscoped/unassigned alerts cannot be enabled for them, and recent alerts recheck lead IDs rather than trusting recipient history. Keep management visibility and allocation unchanged.
- CRM attendance uses a dedicated session ledger and per-user serialized server clock, separate from allocation presence; JWT-checked service-only recording owns timestamps and totals, while management-only reporting separates meaningful use from open-session time.
- Attendance composes existing RLS-protected location and lifecycle logs; staff authentication history uses a service-only allowlisted RPC with protected admin-role checks and bounded pagination, never raw authentication payloads or inferred identities.
- Approved-browser access stores credential hashes and explicit admin decisions server-side; staged enforcement stays disabled until administrator enrolment and every data entry point are verified. Browser credentials are bearer proofs, not hardware identity; no automatic first-device approval.
- Call data bookmarks share the existing tab_overview permission through one helper used by sidebar and render guards; preserve underlying call scopes, collection and attribution.
- Linked renewals reuse the New Leads call counter, dial/email/reminder controls and full notes panel keyed by the existing lead ID; preserve policy outcomes and routing so activity stays with the same lead across views.
- Cyber security is read-only and admin/super-admin-only; a service-only summary RPC checks protected roles and returns counts, while a JWT-checked endpoint inspects only fixed published URLs, so no secrets or customer records enter reports.
- Keep CLI asset pointers; portableAssetsPlugin resolves external-host URLs; mobile caps sit on wrappers.
- Abandoned Cart lists and exports use the shared fail-closed eligibility loader and active-staff-checked history RPC returning only excluded cart IDs, keeping restricted claims data server-side and barring cancelled/refunded customers.
- SEO Audit/semrush-seo share chat and permissions; dated audit + RLS evidence, no Semrush/live-scan claims. Shared guides separate approval from edits/publication; thread archived_at preserves private readable history.
- Weekly SEO reviews use database-queued, idempotent server-side published-site reads and private access-checked review records; only super admins decide proposals, and decisions never execute edits or publication. The selected SEO account receives a dedicated review grant without expanding assistant permissions.
- Missing metadata uses existing prerender inventory/static sitemap, one entry per path; preserve schema. Shared image resolver/approved alt serve sharing and article images; preserve descriptions and stable URLs, omit unverified dimensions.
- Careers contact/experience requirements use a shared pure validator in the form and submission function, with strict server schemas, so bypassing browser controls cannot admit an ineligible application.
- Careers rejection deadlines are stamped from dedicated settings in the database; postponement uses an access-checked RPC and the sweep uses an atomic dedicated lease. CV previews use short-lived signed storage links and render Word files as plain text.
- New pricing versions use `websiteDiscountMode: single` on completed totals; preserve legacy rules. Percentage changes use a validated pure matrix transform and existing draft save; update the editor only on success, never auto-publish.
- The named pricing-plan dialog owns grid and vehicle edits; hydrate only selected-plan figures, carry unknown model fields, and save explicit plan percentages instead of browser-wide defaults so separate plans cannot contaminate each other. Signed website differences reuse the existing formula and floors; saving never publishes.
- Saved pricing-plan actions open the named dialog directly; read-only comparisons use matching cells from the loaded live version (code fallback only without a live version) and compare already calculated totals, never altering pricing overrides.
- Published document blogs may supply exact article HTML and schema through route metadata so crawler output preserves the same approved content as the database article without altering existing page schemas.
- Reuse CallMeBackPanel/sandbox-callback-request for callback leads. Gate live offers/requests on server config plus fresh presence; management changes it via the availability endpoint. Pair question replies to their turn; drafts need explicit approval.
- Use the shared sale-subject formatter for manager direct-sale email source labels in both subject and body; keep existing attribution and delivery logic unchanged to avoid affecting payment flows.
- ORR uses one sandbox, with a page-level practice-view switch hiding manager controls, not changing permissions; Lead Allocation mirrors read-only.

- Analytics goals stay separate in `monthly_revenue_targets`; shared month selector/bar shape preserve maths. Daily seller grouping is presentation-only, never changes sale credit.
- Multi-year quotes offer 12 instalments or BAW PayLater. Shared yearlySaleRevenue avoids double division; paginated paid anniversaries use collection date and sale owner, never new-deal credit; future money is not revenue.
- A manual Quotes & Orders total is the final BAW PayLater term total; split it across yearly collections without adding the standard 10% uplift again.
- Route renewal leads only to active agents with the Renewals workstream; prefer the original seller, otherwise use longest-waiting rotation so new starters never receive catch-up batches.
- Auto-create renewals only without claim/cancel/refund history; others wait in Renewal approval until recorded management approval to re-offer cover.
- Keep the sales phone availability rule separate from live-chat presence: phone calls are offered Mon–Fri 9am–6pm and Sat 12pm–4pm UK time, with callback/WhatsApp outside those hours.
- Date of birth is collected on Bumper's own page, not in our Step 4; Step 4 hands straight to Bumper after validation so payment pricing and provider logic stay shared.
- The CRM Agentic Assistant is read-only; super admins get every part, other staff only the parts granted via tab_growth-* permissions (checked server-side + RLS); it suggests actions but must never get tools that change data or send messages, so nothing happens without a person acting.
- Lead count tab: visibility = admin/super_admin or tab_lead-count grant, never sales roles; data via get_lead_count_report RPC (checks server-side) using locked daily snapshots.
- Lead quality: private read-only RPC; outcomes never rewrite snapshots.
- Reporting: immutable invoices, locked payments, service-only email claims; hourly job only when enabled, independent of staff commissions.
- Login: fail-open check_login_lockout (5/15min); service-only staff renewal records enforce expiry through a PostgREST pre-request hook and shared edge authentication; self-renewal verifies the current password. Gateway changes remain active-admin-only with versioned receipts and password-free active-staff notices.
- Auth-state callbacks must defer Supabase work until after the auth lock is released; staff access checks are bounded and single-flight so a stalled request cannot leave the login screen spinning indefinitely.
- Keep the homepage journey route lazy-loaded so staff sign-in does not download homepage-only forms and quote delivery; retain all route-level security gates.
- Detailed call totals refresh single-flight every 30 seconds only while visible and on returning from the dialler; paginate call events with timestamp/id ordering and retain last successful figures on failure to avoid stale or truncated agent counts.
- PayLater claim flags use a service-only protected-role lookup through authenticated edge access, returning customer IDs only; match linked policies first and batch-load matches before pagination to retain older records without exposing claim details.
- Handover backups stay atomic; indexed normalized ownership lookups and bounded per-RPC timeouts prevent large transfers timing out.
- Payment-click reads require active staff; call-event writes require the caller's own active staff ID, and lead/allocation audit writes stay system-only so client accounts cannot forge history. Staff archiving must explicitly reject a missing management role.
- Bulk pricing imports require the shared active-admin authentication guard before parsing updates; preserve existing calculations after authorization to protect live prices.
- Customer-data exports recheck a shared server permission before downloads; only active admin/super-admin have default access, and other staff require a separately RLS-protected export grant managed only by those roles. Grants are scoped per surface in staff_export_grants: can_export_new_leads (New Leads + Recontact), can_export_customers (Customer Management), can_see_lead_source (source column in Customer Management, New Leads, Recontact); all default off, and the legacy can_export_customer_data() is the OR of both export scopes. Export grants never widen table RLS or prevent copying already-readable records.
- Quote lead imports use ownership-scoped searches, skip customer/cart fallback for sales roles and recheck current ownership before filling the form; the shared search RPC scopes sales callers server-side without changing allocation or quote pricing.
- Personal New Leads progress/attendance visibility uses a default-off per-agent team setting guarded by management-only writes; display changes never alter attendance recording or management reports.
- Restored lost/archived leads return on a management hold (unassigned, hidden from sales/sales_lead queries, search and pool claiming); any assignment releases the hold via trigger. The restore panel is gated by `canAccessLeadsArchive` (tabAccess.ts): admin/super_admin always, others need the `tab_new-leads_leads-archive` grant.
