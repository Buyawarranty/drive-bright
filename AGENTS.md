# Project architecture rules
- Lead/checkout RLS enforces ownership, including failed-payment rows/sounds/claims and lookups. Access events stamp actor/server time; opens/copies log apart from seen receipts. Allocation stays separate.
- Step 2/4 and Payment Assist share mobile validation; both Step 2 variants share a heading.
- Postcoder autocomplete uses key-in-query URLs and town pathfilters, avoiding HTML responses.
- Customer/lead pop-ups and notification bells share a fail-closed current-assignee check for sales and sales leads, including WhatsApp replies and policy-linked authorisation results; unscoped/unassigned alerts cannot be enabled and recent alerts recheck lead IDs, not recipient history. Ownership reads accept only the latest request and clear approval during revalidation, so delayed reads cannot restore a former owner's alerts. 
- CRM attendance uses a dedicated session ledger and per-user serialized server clock, separate from allocation presence; JWT-checked service-only recording owns timestamps and totals, management-only reporting separates use from open-session time.
- Attendance reports deduplicate requests per date range and accept only the currently selected range, so a pending live refresh cannot block or overwrite historical searches; date choice never mutates stored attendance. Daily timelines split sessions at the selected display-zone day boundary, preserve repeats and stop at observed last-seen times; a reconnect after a stale heartbeat opens a new attendance session, so saved authentication never implies continuous presence or a computer lock.
- Daily activity bars use recorded UK-day active aggregates separately from recoverable final-interaction idle tails; concurrent unknown activity removes idle evidence, and legacy session endpoints never imply complete historical active/idle transitions. First CRM presence takes the earliest valid selected-period session start or RLS-protected location observation and labels its source; observations never add active seconds or fill gaps.
- Attendance composes existing RLS-protected location and lifecycle logs; staff authentication history uses a service-only allowlisted RPC with protected admin-role checks and bounded pagination, never raw payloads.
- Attendance location review reuses paginated RLS-protected work-location records with shared dates and staff scope; multiple network/place/device-type signals prompt review, never automatic denial or a physical-device identity claim.
- Approved-browser access stores credential hashes and explicit admin decisions server-side; enforcement stays disabled until administrator enrolment and every data entry point are verified. Browser credentials are bearer proofs, not hardware identity; no automatic first-device approval.
- Call bookmarks share tab_overview via sidebar/render guards; preserve call scopes, collection and attribution.
- Linked renewals reuse the New Leads call counter, dial/email/reminder controls and full notes panel keyed by the existing lead ID; preserve policy outcomes and routing so activity stays with the same lead across views.
- Cyber security is read-only, admin/super-admin-only: a service-only summary RPC checks protected roles and returns counts, and a JWT-checked endpoint inspects only fixed published URLs, so no secrets or customer records enter reports.
- Keep CLI asset pointers; portableAssetsPlugin resolves external-host URLs; mobile caps sit on wrappers.
- Abandoned Cart lists and exports use the shared fail-closed eligibility loader and active-staff-checked history RPC returning only excluded cart IDs, keeping restricted claims data server-side and barring cancelled/refunded customers.
- SEO Audit/semrush-seo share chat and permissions; dated audit + RLS evidence, no Semrush/live-scan claims, and shared guides separate approval from edits/publication (thread archived_at keeps private history readable). Weekly reviews use database-queued, idempotent server-side published-site reads and private access-checked records; only super admins decide proposals and decisions never execute edits or publication. The selected SEO account gets a dedicated review grant without expanding assistant permissions.
- Missing metadata uses existing prerender inventory/static sitemap, one entry per path; preserve schema. Shared image resolver/approved alt serve sharing and article images; preserve descriptions and stable URLs, omit unverified dimensions.
- Careers contact/experience requirements use a shared pure validator in the form and submission function with strict server schemas, so bypassing browser controls cannot admit an ineligible application. Rejection deadlines come from dedicated database settings; postponement uses an access-checked RPC and the sweep an atomic dedicated lease. CV previews use short-lived signed storage links and render Word files as plain text.
- New pricing versions use `websiteDiscountMode: single` on completed totals; preserve legacy rules. Percentage changes use a validated pure matrix transform and existing draft save; update the editor only on success, never auto-publish.
- The named pricing-plan dialog owns grid and vehicle edits: hydrate only selected-plan figures, carry unknown model fields, and save explicit plan percentages rather than browser-wide defaults so plans cannot contaminate each other; saved actions open it directly. Read-only comparisons use matching cells from the loaded live version (code fallback only without one) and compare already calculated totals, never altering overrides. Signed website differences reuse the existing formula and floors; saving never publishes.
- Published document blogs may supply exact article HTML and schema via route metadata, so crawler output keeps the same approved content as the database article without altering existing page schemas.
- Reuse CallMeBackPanel/sandbox-callback-request for callback leads. Gate live offers/requests on server config plus fresh presence, changed by management via the availability endpoint. Pair question replies to their turn; drafts need explicit approval.
- Use the shared sale-subject formatter for manager direct-sale email source labels in both subject and body; keep existing attribution and delivery logic unchanged to avoid affecting payment flows.
- ORR shares one sandbox; practice view hides controls without changing permissions; Lead Allocation mirrors read-only.
- Goldmine releases share a guarded allocation RPC and role/count validation; legacy self-claim fails closed to prevent bypasses.

- Analytics goals stay separate in `monthly_revenue_targets`; shared month selector/bar shape preserve maths. Daily seller grouping is presentation-only, never changes sale credit.
- Multi-year quotes offer 12 instalments or BAW PayLater. Shared yearlySaleRevenue avoids double division; paginated paid anniversaries use collection date and sale owner, never new-deal credit; future money is not revenue.
- A manual Quotes & Orders total is the final BAW PayLater term total; split it across yearly collections without adding the standard 10% uplift again.
- Route renewal leads only to active agents with the Renewals workstream; prefer the original seller, otherwise use longest-waiting rotation so new starters never receive catch-up batches.
- Auto-create renewals only without claim/cancel/refund history; others wait in Renewal approval until recorded management approval to re-offer cover.
- Keep the sales phone availability rule separate from live-chat presence: calls are offered Mon–Fri 9am–6pm and Sat 12pm–4pm UK time, with callback/WhatsApp outside those hours.
- Date of birth is collected on Bumper's own page, not in our Step 4; Step 4 hands straight to Bumper after validation so payment pricing and provider logic stay shared.
- The CRM Agentic Assistant is read-only; super admins get every part, other staff only parts granted via tab_growth-* permissions (server-side + RLS); it suggests actions but must never hold tools that change data or send messages, so nothing happens without a person acting.
- Lead count tab: visibility = admin/super_admin or tab_lead-count grant, never sales roles; data via get_lead_count_report RPC (checks server-side) using locked daily snapshots.
- Lead quality: private read-only RPC; outcomes never rewrite snapshots.
- Reporting: immutable invoices, locked payments, service-only email claims; hourly job only when enabled, independent of staff commissions.
- Login: fail-open check_login_lockout (5/15min); service-only staff renewal records enforce expiry through a PostgREST pre-request hook and shared edge authentication; self-renewal verifies the current password. Gateway changes remain active-admin-only with versioned receipts and password-free active-staff notices.
- Auth-state callbacks defer Supabase work until the auth lock is released, and staff access checks are bounded and single-flight so a stalled request cannot leave the login screen spinning. Staff password sign-ins on /auth await token-validated active-admin_users session revocation before navigation; revoke-others bypasses device approval, rejects customers and never runs for restored/refocused sessions, keeping device rollout separate.
- Keep the homepage journey route lazy-loaded so staff sign-in does not download homepage-only forms and quote delivery; retain all route-level security gates.
- Detailed call totals refresh single-flight every 30s only while visible and on return from the dialler; paginate call events by timestamp/id and retain last successful figures on failure so agent counts stay complete.
- PayLater claim flags use a service-only protected-role lookup through authenticated edge access, returning customer IDs only; match linked policies first and batch-load matches before pagination to retain older records without exposing claim details.
- Handover backups stay atomic; indexed normalized ownership lookups and bounded per-RPC timeouts prevent large transfers timing out.
- Payment-click reads require active staff; call-event writes require the caller's own active staff ID, and lead/allocation audit writes stay system-only so client accounts cannot forge history. Staff archiving must explicitly reject a missing management role.
- Bulk pricing imports require the shared active-admin authentication guard before parsing updates; preserve existing calculations after authorization to protect live prices.
- Customer-data exports recheck a shared server permission before downloads; only active admin/super-admin have default access; other staff need an RLS-protected grant from those roles. staff_export_grants scopes each surface (can_export_new_leads for New Leads + Recontact, can_export_customers for Customer Management, can_see_lead_source for the source column in those three views), all default off, and legacy can_export_customer_data() is the OR of the two export scopes. Grants never widen table RLS or prevent copying already-readable records.
- Quote lead imports use ownership-scoped searches, skip customer/cart fallback for sales roles and recheck current ownership before filling the form; the shared search RPC scopes sales callers server-side without changing allocation or quote pricing.
- Personal New Leads progress/attendance visibility uses a default-off per-agent team setting guarded by management-only writes; display changes never alter attendance recording or management reports.
- Restored lost/archived leads sit on a management hold (unassigned, hidden from sales/sales_lead queries, search and pool claiming) until any assignment releases it via trigger. The restore panel uses `canAccessLeadsArchive` (tabAccess.ts): admin/super_admin always, others need the `tab_new-leads_leads-archive` grant.
- Customer name/phone validation lives in shared pure helpers (src/lib/firstNameRule.ts, supabase/functions/_shared/ukCheckoutPhone.ts, ukPersonName.ts) shown as the customer types, so page, tests and server never disagree; an empty field stays quiet until the button is pressed; phone boxes strip letters, name boxes digits.
- Rapid lead-opening alerts wake from a trigger, never polling; only openings with no matching dial count, so unanswered dials are exempt; admins and super admins only.
